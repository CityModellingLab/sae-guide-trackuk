Unit-Level SAE Modelling (Battese–Harter–Fuller)

A Bayesian spatio-temporal extension

Theory in brief

The unit-level route models respondent outcomes directly. For the area-time target \mu_{jt}, a simple mixed-model form is:

Y_{ijt} = \alpha + x_{ijt}^{T}\beta + u_j + v_t + \epsilon_{ijt},

where x_{ijt} contains unit-level predictors, u_j is an area effect, and v_t is a time effect. The area effect can be replaced by a structured spatial effect, and a temporal effect v_t can be added to represent wave-to-wave dependence. To estimate the target for an area-time cell, the fitted model is evaluated using the corresponding population-level auxiliary summaries \bar{x}_{jt}:

\hat{\mu}_{jt}^{\mathrm{BHF}} = \widehat{\mathbb{E}}(Y \mid j,t,\bar{x}_{jt}).

Estimation approach

Target estimand
  • Outcome and Population: Share of Adults who walk for transport daily
  • Geography: MSOAs in Wales
  • Time: 2021, 2023, and 2025

Unit-level SAE models respondent records directly instead of modelling pre-aggregated direct estimates. For our estimand, the Battese–Harter–Fuller model estimates the binary frequent-walking indicator from survey records using unit-level age, sex, and car_access predictors, together with spatial and temporal random effects.

The fitted model is then used to predict the target MSOA-year estimates using MSOA-level summaries of age, sex, and car access, obtained from ONS UK Census 2021. This avoids relying directly on unstable area-level direct estimates, but introduces new assumptions about how adequately or inadequately area-level summaries represent the population composition.

1 Prepare model and aggregation data

Before preparing the model inputs, we create consistent numeric indices for each area and survey year so that INLA can attach random effects to the correct area and period, as well as a Queen-contiguity adjacency graph .adj as input, similar to what we did in the previous FH model estimation.

area_levels <- sort(unique(domain_frame[["area_id"]]))
time_levels <- sort(unique(domain_frame[["time_id"]]))

area_index <- tibble(
  area_id = area_levels,
  area_inla_id = seq_along(area_levels)
)

time_index <- tibble(
  time_id = time_levels,
  time_inla_id = seq_along(time_levels)
)
msoa_boundaries_sorted <- msoa_boundaries |>
  inner_join(area_index, by = "area_id") |>
  arrange(area_inla_id)

msoa_neighbours <- poly2nb(
  msoa_boundaries_sorted,
  queen = TRUE,
  row.names = msoa_boundaries_sorted$area_id
)

spatial_graph_file <- tempfile(fileext = ".adj")

nb2INLA(
  file = spatial_graph_file,
  nb = msoa_neighbours
)

We now prepare the two datasets needed for the unit-level INLA workflow:

  • model_data contains the sampled respondent records used to fit the model.
  • aggregation_data contains one row for each area-time cell we want to estimate.

1.1 Respondent model data

The respondent model data has one row per sampled person. For this example we use:

  • indicator as the binary response, our target;
  • age as a unit-level predictor;
  • female as a binary unit-level predictor;
  • car_access as a unit-level predictor;
  • time_id as the survey wave year identifier;
  • area_id as the area identifier;

2 Fit and evaluate models

We fit linear mixed models to respondent-level records, then use them to predict area-time means. Because the response variable is binary, the fitted values are interpreted as predicted probabilities.

We specify three unit-level models to evaluate at the next step:

Model Name Specifications
M1 +TempSpatial Respondent outcome with a temporal random walk and BYM2 spatial MSOA effect
M2 +Demographic M1 plus respondent age and sex
M3 +CarAccess M2 plus respondent-level car access

Conceptually, the workflow has two steps: fit the respondent-level model, then evaluate it for each area-time. We implement this by binding the observed respondent rows and the area-time aggregation rows into a single input table before fitting. The area-time rows to have their estimates predicted have indicator = NA, signalling to INLA to return fitted values for them.

model_agg_data <- bind_rows(
  model_data |>
    mutate(row_type = "model"),
  aggregation_data |>
    mutate(
      row_type = "aggregation",
      indicator = NA_real_
    )
) |>
  select(
    row_type, 
    indicator, 
    age, 
    female, 
    car_access, 
    time_inla_id, 
    area_inla_id
    )

fit_bhf_model <- function(formula) {
  inla(
    formula = formula,
    family = "gaussian",
    data = model_agg_data,
    control.predictor = list(compute = TRUE),
    control.compute = list(waic = TRUE, config = TRUE)
  )
}

bhf_fits <- lapply(model_formulas, fit_bhf_model)
Note

When fitting unit-level BHF models with INLA, these arguments are needed:

  • control.predictor = list(compute = TRUE) ensures that fitted values are returned for the full input table, so the predictions for the aggregation rows can be extracted after fitting.
  • control.compute = list(waic = TRUE) requests WAIC for comparing model fit across candidate specifications.

To compare the fitted models’ overall performance, we again use WAIC as a first check, a global predictive-fit measure returned by INLA. Lower values indicate better expected prediction after penalising model complexity. Here, the lower WAIC for M3 shows that adding the car-access predictor improves the model predictive power as expected.

3 Final estimates and uncertainty

Using M3 as the selected model, we extract predictions for the target area-time rows, marked in the INLA input as row_type == "aggregation". We then report the posterior mean as the final estimate and use the lower and upper bounds of the 95% credible interval to describe uncertainty.

In practice, modelled estimates should always be reported alongside the direct-estimate metadata. This keeps the sample size, direct estimate, and direct-estimate variance in the final output, making it easier to compare the modelled result with the survey evidence it builds on.

bhf_m3_fitted_values <- bhf_fits[["M3 +CarAccess"]]$summary.fitted.values |>
  as_tibble() |>
  slice(which(model_agg_data$row_type == "aggregation"))

bhf_m3_results <- bind_cols(
  aggregation_data |> select(area_id, msoa_name, time_id),
  bhf_m3_fitted_values
) |>
  transmute(
    area_id,
    msoa_name,
    time_id,
    bhf_estimate = pmin(pmax(mean, 0), 1),
    bhf_variance = sd^2,
    bhf_lower = pmin(pmax(.data[["0.025quant"]], 0), 1), # clipped to [0,1] since estimate is a share
    bhf_upper = pmin(pmax(.data[["0.975quant"]], 0), 1), # clipped to [0,1] since estimate is a share
    bhf_ci_width = bhf_upper - bhf_lower
  )

However, the BHF and Fay–Herriot estimates for each small area can still differ because the two models use the survey information differently. The BHF model is fitted to unweighted respondent records, while the Fay–Herriot model starts from weighted direct estimates and their sampling variances to model area-year estimates. As a result, unstable direct estimates can affect the Fay–Herriot results, whereas the BHF model may be inaccurate if the complex survey design and weights are ignored. In general, for scenarios where rich survey microdata is present, a unit-level approach is preferred.

That said, although the model is fitted with unit-level predictors, the aggregation step relies on strong assumptions about each area’s population composition. Representing age, sex, and car access with area-level summaries, such as mean age, proportion female, and share of households with car access, can hide important compositional differences. Two areas may have similar summaries but very different age-sex-car structures, meaning the model could produce similar estimates even where walking behaviour differs across specific combinations of these predictors.

This limitation can be addressed by using a poststratification table that contains population counts for the joint distribution of the relevant predictors. This is the logic of Multilevel Regression with Poststratification (MRP), predict the outcome for each poststratification cell, then aggregate those predictions using the corresponding population counts so the final estimates better reflect the target population composition.
